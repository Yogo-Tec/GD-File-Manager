Local File Manager

A Windows desktop file manager and creative asset workspace for graphic designers. Build a real, reliable application that works directly with the user's local filesystem.

Windows 10 / 11 Tauri 2 React + TypeScript Rust + SQLite Offline-first
Primary product decision: This is an advanced file manager with a strong graphic-designer asset-management focus. Build the real filesystem engine and dependable core workflows first. AI, MCP, ChatGPT, Gemini and voice are explicitly deferred until the core application is stable.

1. Product vision

Create a professional Windows desktop application that gives creative professionals fast, safe and organized control over files, folders, drives and design assets.

Real file management

Browse, scan, search, copy, move, rename and organize actual Windows files and folders.

Creative asset workflow

Preview, inspect, tag, compare and collect images, fonts, vectors and design documents.

Reliable operations

Preview bulk changes, detect conflicts, show progress and maintain an operation journal.

Offline-first

Normal file management must work without an internet connection or cloud account.

3. Functional modules

3.1 Dashboard and storage analytics

  • Detected drives, capacity, used space and free space.
  • Indexed file count, folder count and total indexed size.
  • File-type distribution, largest files and largest folders.
  • Recent files, recently modified files, favorites and recent operations.
  • Scan status, progress and error summaries.
  • Storage charts and folder-size visualization.

3.2 Drive and folder scanner

  • Scan selected folders, complete drives and multiple drives recursively.
  • Incremental scanning, pause, resume and cancel.
  • Configurable folder and extension exclusions.
  • File/folder counts, sizes, extensions, timestamps and attributes.
  • Handle inaccessible files, permission errors, removable drives and locked files gracefully.
  • Persist scan sessions and report skipped paths and errors.
  • Use filesystem notifications where practical, plus periodic reconciliation scans.

3.3 Professional file explorer

  • Grid, detailed list and compact list views.
  • Dual-pane navigation and folder tree.
  • Breadcrumbs, back, forward, up and quick access.
  • Real drag-and-drop, multi-selection and context menus.
  • Copy, cut, paste, move, create folder, rename and delete.
  • Sort and configurable columns; show hidden files and extensions.
  • Open with the default Windows application and view file properties.
  • Virtualize large result lists; never render millions of rows at once.

3.4 Advanced search and filters

  • Search by filename, extension, file type, location, size and dates.
  • Search extracted text in supported formats.
  • Search image dimensions, resolution, metadata and tags when indexed.
  • Operators: AND, OR, NOT, contains, starts with, ends with, equals, greater/less than, between, regex and fuzzy matching.
  • Nested visual rule builder, saved searches and search history.
  • Clearly indicate whether a result is indexed, unavailable or unsupported for content search.

3.5 Bulk rename

  • Prefix, suffix, replacement, removal and case conversion.
  • Sequential numbering, configurable start and zero padding.
  • Date-based and custom filename patterns.
  • Regular expressions and extension handling.
  • Show old and proposed names before execution.
  • Validate collisions, invalid Windows characters, path limits and stale file references.

3.6 Smart organizer

  • Rules based on extension, type, dates, dimensions, metadata and filename patterns.
  • Nested AND/OR/NOT rule groups.
  • Custom destination and folder templates.
  • Copy or move mode, dry-run preview and conflict handling.
  • Per-file results, cancellation and operation report.

3.7 Shortlists and collections

  • Multiple named collections containing references to real source files.
  • Add results from different folders and drives.
  • Remove entries, preview assets and detect repeated entries.
  • Copy selected files to a destination, preserving folder structure or flattening it.
  • Export a collection manifest with original locations.
  • Report missing or changed source files; do not fabricate replacement files.

3.8 Duplicate finder

  • Exact duplicate detection using SHA-256 after a file-size pre-filter.
  • Similar-image detection using perceptual hashing and a configurable threshold.
  • Group results and provide side-by-side comparison.
  • Show original locations, sizes and image dimensions.
  • Offer selection suggestions but never auto-delete.
  • Use Recycle Bin for supported deletion and require explicit confirmation.

3.9 Preview and file inspection

  • Images: JPG, JPEG, PNG, WebP, BMP, GIF and compatible TIFF.
  • Vectors/documents: SVG, PDF and compatible EPS/AI/PSD preview paths.
  • Text: TXT, MD and CSV; compatible DOCX preview if a suitable renderer is available.
  • Optional video preview for supported MP4/MOV codecs.
  • Zoom, pan, rotate, fit-to-screen, full-screen and multi-file navigation.
  • Contact sheets, image comparison and metadata inspector.
  • Preview support must be documented separately from conversion support.

3.10 Batch conversion and processing

  • Compatible image conversions: JPG, PNG, WebP, BMP and TIFF as supported.
  • SVG rasterization and PDF-to-image only with tested compatible libraries.
  • Batch resizing, compression, aspect-ratio preservation and watermarking.
  • Output naming rules, output directory, progress and per-file error reports.
  • Preserve original files by default; overwrite only after explicit confirmation.
  • Do not claim proprietary design-format conversion unless a compatible converter is actually integrated and tested.

3.11 History, favorites and settings

  • Persistent history for copy, move, rename, delete, conversion, organizer and scan jobs.
  • Undo/recovery actions only when safe and technically possible.
  • Favorite files/folders, pinned locations, recent locations and saved searches.
  • Dark, light and system themes; accent color and explorer preferences.
  • Scan exclusions, cache controls, database backup, diagnostics and privacy settings.

4. Designer-focused asset management

This is the product's primary differentiator. Prioritize these workflows after the filesystem, scanner and explorer are stable.

Metadata manager

Read supported EXIF, IPTC and XMP metadata; keywords, descriptions, copyright and custom tags. Preserve unsupported metadata rather than silently discarding it.

Color palette extractor

Extract dominant colors and expose HEX, RGB and HSL values. Allow copying and saving palettes to collections.

Font discovery

Detect TTF and OTF files, display family metadata and previews, and open fonts with the Windows font viewer. Do not install fonts without a separate explicit user action.

Asset collections

Organize logos, icons, illustrations, textures, mockups, brushes, templates, stock images and UI components using editable tags and collections.

Image inspector

Show dimensions, aspect ratio, DPI when available, color mode, transparency and embedded color profile.

Creative comparison

Compare two images or design exports side by side with zoom and dimensions visible.

Index integrity: The real filesystem is the source of truth. SQLite metadata can become stale. Revalidate file existence, identity and relevant timestamps before operations. Use migrations, transactions, indexes, foreign keys and an appropriate backup strategy.

7. Real filesystem operation contract

All filesystem reads and mutations must be implemented in Rust using actual Windows paths and filesystem APIs. The frontend must never simulate a successful operation or directly access arbitrary paths.

  1. Receive a typed request and validate its operation type.
  2. Validate source and destination paths, permissions and path relationships.
  3. Check available disk space where relevant, conflicts and file identity.
  4. Generate a complete preflight preview.
  5. Obtain explicit user approval for the proposed operation.
  6. Revalidate immediately before execution to handle changes since preview.
  7. Run in a cancellable, bounded background job.
  8. Report per-file progress, errors and partial completion.
  9. Verify results and persist the operation journal.

Windows-specific requirements

  • Support Unicode filenames and long paths within Windows and dependency constraints.
  • Handle NTFS, removable drives and other supported Windows filesystems gracefully.
  • Handle permissions, locked files, junctions and symbolic links safely.
  • Detect source/destination overlap and prevent recursive copy or move operations.
  • Use Windows Recycle Bin integration for supported deletions.
  • Do not request administrator privileges for ordinary operations.
  • Do not follow links outside an approved operation scope without explicit policy and validation.

8. Safety, recovery and privacy

Conflict resolution

Provide Skip, Replace (explicit confirmation), Auto-rename, Manual rename and Cancel. Recheck conflicts at execution time; a preview is not a guarantee that the filesystem remains unchanged.

Rollback limitations

OperationRecovery approach
RenameRestore prior name if the original path is available and safe.
MoveMove back only if the recorded destination still matches and the source can be restored.
CopyRemove only verified copies created by the operation, after checking they have not been modified.
DeleteUse Recycle Bin where supported; permanent deletion cannot be reliably undone without backup.
ConversionPreserve original; remove generated output only after validating its identity.
Metadata editRestore only if previous metadata was captured and the format supports safe restoration.

Privacy and security

  • No mandatory account, cloud storage or internet connection.
  • Use least-privilege Tauri capabilities and narrowly scoped backend commands.
  • Validate paths and guard against path traversal and unsafe link handling.
  • Do not send filenames, paths, metadata, thumbnails or file content to AI services without explicit informed permission.
  • Provide a clear AI data-sharing preview and a global AI disable option when AI is later introduced.
  • Keep secrets out of source code, logs and frontend bundles.

9. Performance and scalability

  • Support large drives and very large directory trees using streaming traversal and bounded queues.
  • Use cursor-based or paginated queries and virtualized frontend lists.
  • Generate thumbnails asynchronously and cache them on disk.
  • Use thumbnail sizes appropriate to the UI; do not decode full-resolution images for grid cells.
  • Use incremental indexing and batched database writes.
  • Use FTS5 and appropriate indexes for search.
  • Bound concurrent hashing, preview generation and conversion according to hardware and drive type.
  • Support cancellation for all long-running jobs.
  • Keep the UI responsive and expose progress, pause/resume where supported, and clear error states.
  • Handle removable drives disappearing during scans or operations.
  • Measure performance on representative SSD, HDD and large-library test datasets; do not promise universal scan speeds.

11. Development roadmap

Implement sequentially. Each phase must end with working, tested functionality—not just UI screens.

PHASE 1 · FOUNDATION

Project setup and filesystem engine

Tauri setup, React architecture, Rust modules, SQLite migrations, drive detection, real file/folder operations, permission handling, path validation and operation journal foundation.

Deliverable: A working desktop foundation with verified real file operations.
PHASE 2 · SCANNING

Scanner and indexing

Recursive scanning, incremental indexing, exclusions, statistics, background jobs, progress, cancellation and scan history.

Deliverable: Real local storage scanner and indexed metadata.
PHASE 3 · DISCOVERY

Explorer, preview and search

Grid/list/dual-pane explorer, virtualized results, thumbnail cache, advanced search, FTS5, nested filters and saved searches.

Deliverable: Functional file discovery workspace.
PHASE 4 · ORGANIZATION

Rename, organizer and collections

Bulk rename preview, smart rules, dry-run, conflict resolution, shortlists, collections and favorites.

Deliverable: Complete organization toolkit.
PHASE 5 · DESIGNER WORKFLOWS

Creative asset management

Image and document previews, metadata, color extraction, font discovery, contact sheets and image comparison.

Deliverable: Designer-focused asset manager.
PHASE 6 · PROCESSING

Duplicates and batch conversion

Exact and similar image detection, supported conversions, resize, compression, watermarking and storage analytics.

Deliverable: Advanced processing suite.
PHASE 7 · RELEASE

Stability and packaging

Crash recovery, rollback validation, performance tuning, Windows integration tests, diagnostics, installer and update mechanism.

Deliverable: Production-ready advanced release candidate.
Future extension after core stability: MCP, ChatGPT, Gemini, voice recognition, text-to-speech and permission-controlled AI actions. Do not make these dependencies of the core application.

12. Testing and quality assurance

  • Rust unit tests for path validation, scanner logic, operation planning and recovery rules.
  • React component and interaction tests.
  • Windows integration tests against temporary real directories and files.
  • Test nested folders, Unicode names, long paths and inaccessible directories.
  • Test locked files, removable drives and permission-denied cases.
  • Test name conflicts, source/destination overlap and stale previews.
  • Test partial failures, cancellation and application restart during jobs.
  • Test hash correctness and duplicate grouping.
  • Test conversion output and verify source preservation.
  • Test thumbnail cache invalidation after file changes.
  • Test large directories and bounded memory/worker behavior.
  • Test offline functionality and confirm no unauthorized network transmission.

13. Release acceptance checklist

  • All core operations affect actual Windows files and folders.
  • Recursive scanning and accurate indexed statistics work.
  • Incremental scans and exclusions work.
  • Explorer grid, list and dual-pane workflows work.
  • Search and nested filters return verified results.
  • Bulk rename has a complete preflight preview.
  • Organizer has dry-run, conflict handling and per-file results.
  • Collections reference real source files and report missing items.
  • Supported previews work and unsupported formats are clearly reported.
  • Exact duplicate detection uses verified content hashes.
  • Conversion preserves originals by default.
  • History persists after restart.
  • Recovery behavior is tested and rollback limitations are disclosed.
  • Long-running work does not freeze the UI.
  • Normal file management works offline.
  • No fake filesystem operations or hardcoded demo success states remain in production paths.
  • Windows installer and release documentation are available.

14. Instructions for Antigravity AI

Build this as a real application, not a mockup. Use this document as the product requirements source of truth.
  1. First inspect the existing workspace and identify whether a project already exists. Preserve useful existing work.
  2. Before coding, propose a concise implementation plan, module boundaries, dependency choices and database schema. Identify any format-support limitations.
  3. Implement Phase 1 first. Do not attempt to generate every feature in one giant component or one coding pass.
  4. Keep the application buildable after each milestone. Run the relevant tests and fix regressions before moving forward.
  5. Implement actual filesystem operations in Rust. Never use mock data to represent successful file operations.
  6. Use temporary test directories for automated destructive-operation tests. Never run destructive tests against a user's real data.
  7. Use typed frontend/backend interfaces and typed progress events. Keep commands narrowly scoped and validate all inputs in Rust.
  8. Implement previews, preflight validation, conflict handling, cancellation and operation logging before enabling bulk mutations.
  9. Do not claim support for PSD, AI, EPS, DOCX, video or other formats until the chosen renderer or converter has been integrated and tested.
  10. Keep AI, MCP, cloud and voice features deferred. They must not block or compromise offline core functionality.
  11. Document setup, development commands, tests, architecture, dependencies, known limitations and Windows packaging.
  12. At the end of every phase, report completed functionality, files/modules changed, tests run, test results, known limitations and the next milestone.

First task for the coding agent

Inspect the workspace, create or refine the Tauri 2 + React + TypeScript + Rust project foundation, define the SQLite migration strategy and implement a small, fully tested Rust filesystem service for listing directories, reading metadata, creating folders, copying, moving and renaming files. Add safe temporary-directory integration tests. Do not begin bulk destructive operations until preflight validation, conflict handling and operation logging are in place.
